# API Design Principles

Trace Trail's HTTP APIs follow predictable, resource-first conventions to keep
backend and frontend teams aligned. This document captures the contract-level
decisions that guide new endpoints.

---

## Naming & Structure

- Base URL: `https://api.tracetrail.com` (local: `http://localhost:8000`).
- Versioning: path-based (future `v1`, `v2`). Today, endpoints live at root but
  include `X-API-Version` headers for clients that need it.
- Routes are grouped by feature (auth, analysis, dashboard, etc.) and align with
  folder names in `backend/src/<module>/router.py`.

Example:

```
POST /analysis/run
GET  /analysis/summary
```

---

## Request/Response Format

- JSON payloads with `camelCase` keys for client ergonomics.
- Standard envelope:

```json
{
  "status": "success",
  "data": { ... },
  "meta": {
    "requestId": "uuid",
    "timestamp": "2025-01-01T00:00:00Z"
  }
}
```

- Errors use:

```json
{
  "status": "error",
  "error": {
    "code": "ANALYSIS_NOT_FOUND",
    "message": "No analysis found for user",
    "details": {}
  }
}
```

Handlers live in `src.shared.exceptions`.

---

## Authentication & Authorization

- All protected endpoints require an `Authorization: Bearer <token>` header.
- Role enforcement is implemented through FastAPI dependencies (see
  `auth/dependencies.py`).
- Sensitive endpoints (reports export, admin dashboards) will additionally check
  scopes when multi-tenant mode is introduced.

---

## Pagination & Filtering

- Use query params: `?page=1&pageSize=20`.
- Return metadata inside `meta.pagination`.
- Filtering should accept simple key/value pairs or comma-separated lists
  (e.g. `?platform=instagram,twitter`).

Shared helpers are located in `src.shared.pagination`.

---

## Idempotency & Mutations

- POST endpoints that create resources should be idempotent when possible (e.g.
  dedupe on unique constraints).
- Use PUT/PATCH for updates; PATCH is preferred for partial updates.
- For destructive actions, require confirmation tokens or soft-deletes when user
  data retention policies demand it.

---

## Rate Limiting

- Handled at gateway level for now (Cloudflare/Azure Front Door). Document per
  route limits in `docs/api/*` when they differ from defaults.
- Backend exposes `EXTENSION_RATE_LIMIT` to throttle extension ingest routes.

---

## Documentation

- OpenAPI schema auto-generated by FastAPI. Access via `/openapi.json`.
- Markdown specs live in `docs/api/`.
- Postman collection (`docs/api/postman_collection.json`) mirrors the current
  contract—update it when endpoints change.

---

## Backward Compatibility

- Use additive changes when possible.
- When breaking changes are unavoidable, bump version and maintain both routes
  until clients migrate.
- Track deprecation notices in `CHANGELOG.md` and highlight in release notes.
