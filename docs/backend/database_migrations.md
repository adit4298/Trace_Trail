# Database Migrations

Trace Trail uses Alembic to manage schema changes for the PostgreSQL database.
All migration scripts live under `backend/alembic/`.

---

## Directory Layout

```
backend/
├── alembic.ini
└── alembic/
    ├── env.py
    ├── script.py.mako
    └── versions/   # autogenerated migration files live here
```

`env.py` loads SQLAlchemy metadata from `src.core.database.Base`.

---

## Common Commands

```bash
# Generate a new revision
alembic revision --autogenerate -m "add challenges table"

# Apply migrations
alembic upgrade head

# Downgrade one step
alembic downgrade -1
```

Set the `DATABASE_URL` environment variable (or `.env`) before running Alembic
so it can connect to the correct database.

---

## Authoring Tips

1. Review autogenerated diffs; ensure `nullable`, `default`, and indexes are
   correctly inferred.
2. Keep data migrations idempotent—wrap them in helper functions and check if
   rows already exist before inserting seed data.
3. Update `docs/architecture/database_schema.md` whenever you add/remove tables.
4. If migrations impact user data, write a rollback section in the PR
   description.

---

## Seeding & Fixtures

- Use scripts from `backend/scripts/` (e.g. `seed_data.py`) to populate demo
  data after running migrations.
- Avoid putting seed logic in Alembic migrations unless absolutely necessary.

---

## Troubleshooting

- **Locked migration:** Ensure no other process holds a DB lock. Restart
  PostgreSQL or close pending transactions.
- **Autogenerate misses changes:** Confirm models import the metadata (e.g.
  new tables added to `src/analysis/models.py`). Alembic only sees models
  registered on the Base metadata.
- **Multiple heads:** Run `alembic heads` and merge via
  `alembic merge <head1> <head2> -m "merge heads"`.
